05 · Mesmo percurso, duas expressões

Amigos de amigos: João → Maria → Pedro.

MYSQL · TABELAS + JOINs
SELECT DISTINCT p3.nome
FROM pessoas p1
JOIN amizades a1 ON a1.origem_id=p1.id
JOIN pessoas p2 ON p2.id=a1.destino_id
JOIN amizades a2 ON a2.origem_id=p2.id
JOIN pessoas p3 ON p3.id=a2.destino_id
WHERE p1.nome = 'João';
NEO4J · RELAÇÕES NO MODELO
MATCH (:Pessoa {nome: 'João'})
      -[:SEGUE]->()
      -[:SEGUE]->(amigo)
RETURN DISTINCT amigo.nome;

Expressividade

No MySQL, tabelas e JOINs percorrem as duas relações. No Neo4j, o padrão de conexões aparece diretamente na consulta.

Mesmo resultado

Pedro

Grafos podem ser mais expressivos para relações; não são automaticamente mais rápidos.

07 · Node.js + TypeScript

Do código à chave no Redis.

import { createClient } from 'redis';const redis = createClient();await redis.connect();await redis.set('produto:101', 'Notebook', { EX: 30 });const produto = await redis.get('produto:101');console.log(produto); // Notebook
Aplicação Node.js→Redis→produto:101

createClient cria o cliente; connect estabelece a conexão.

set armazena; EX: 30 define o TTL em segundos.

get recupera o valor pela chave.

12 · Cassandra · da tabela à consulta

Partição primeiro, ordem depois.

CREATE TABLE eventos_usuario ( usuario_id UUID, data_evento TIMESTAMP, tipo_evento TEXT, PRIMARY KEY (usuario_id, data_evento)) WITH CLUSTERING ORDER BY (data_evento DESC);
SELECT * FROM eventos_usuario
WHERE usuario_id = ?;

1. Tabela: CQL tem sintaxe semelhante a SQL.

2. Partition key: usuario_id leva eventos do mesmo usuário à mesma partição lógica.

3. Clustering: data_evento ordena os eventos dentro dessa partição, em ordem decrescente.

4. Consulta: a chave informa qual partição acessar.

Relacional: tabelas, índices e SQL flexível. Cassandra: modelagem pelos padrões de consulta.

CQL não oferece todas as possibilidades de consulta de um banco relacional; o acesso é planejado a partir da chave de partição.

12 · Comparação essencial

Mesmo “colunar”, propósito diferente.

CASSANDRA · WIDE-COLUMN

Operacional e distribuído

Dados por partições, consultas planejadas e CQL. Indicado para cargas operacionais com escala distribuída.

SELECT … WHERE usuario_id = ?

BIGQUERY · ANALÍTICO COLUNAR

Análise e agregação

Consultas analíticas em grandes volumes usando SQL. Não é usualmente classificado como NoSQL.

SELECT SUM(valor) FROM vendas

Cassandra não é um data warehouse; BigQuery não substitui um banco operacional de baixa latência.
